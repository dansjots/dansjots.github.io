Self-contained repo-specific SSH key

2025-12-11

I exclusively set up my repositories with deploy keys, as I don’t to inadvertently push changes from the wrong account due to forgetting to change the machine-wide credential.

I used to keep several subdirectories inside my .ssh directory for per-account keys and manually copy-paste them outside whenever I want to push a specific repo, but it’s cumbersome and still error-prone.

Eventually I came across this SuperUser answer and adopted it with my slight twist by leveraging the fact that the .git directory’s contents are well-behaved and don’t read or modify anything that it doesn’t recognize, so no risk of accidentally committing keys.

Assuming the filename of your private key is id_ed25519 and public key is id_ed25519.pub:

  1. Paste the file id_ed25519 into the .git directory of your current repo, i.e. it should now be located at <your-repo-name>/.git/id_ed25519.
  2. From your repository’s working directory, run in the terminal:
    git config core.sshCommand "ssh -i .git/id_ed25519"
  3. Now any time you push to the origin it will use that private key file instead of the one located in your user profile’s .ssh directory.

Obviously you can use a different filename for your private key, as long as you also change the git config command correspondingly.
